# 产品架构边界

野生流动内容工作台以知识库驱动的人机协作、修改、审核和交付为主要使用方式。
内容工厂持续打磨；先通过具体业务内容工作台交付积累经验，再归纳本仓的自有工作台产品。
后置本仓产品化不影响业务工作台交付。本仓具体体系尚未开始搭建，dsh-oil-creator 是后续形态参照；
Mac、Electron 和 DSH Desktop 是此前候选，见[产品方案](product-plan.md)及其引用的最新决策。

## 候选组成与所有权

以下是已有研究保留的设计输入，不表示已采用全部组件或已经启动实施。

| 层 | 责任 | 处理方式 |
|---|---|---|
| 桌面宿主 | 应用窗口、菜单栏、本地服务启动、端口、更新与诊断 | DSH Desktop 为此前候选；是否采用桌面入口尚待确定 |
| 内容工作台 | 内容列表、项目检查器、对话上下文、阶段和人工确认 | 从业务交付经验归纳，并参考 dsh-oil-creator；具体体系和复用范围尚待确定 |
| Agent 与扩展 | 模型调用、工具、Skills、会话与插件装配 | 使用经验证的 DSH 版本，不默认 Fork 核心 |
| 用户内容 | 正文、引用、图像、音频、视频及成品 | 普通文件与 Markdown；Obsidian 可直接读取和编辑 |
| 可选执行能力 | 转录、字幕、封面、录制/剪辑工程及其他内容生产 | 按需选择 Skills/外部应用，不把第三方账号、作者人设或供应商选择写成产品硬依赖 |

正文以本地文件为准；工作台运行状态与凭据单独保存，不建立隐藏的第二份正文。
内容项目可以包含一种或多种媒体，图文或音频项目不要求先有视频、字幕或录屏工程。

## 自有责任

- 本产品的安装入口、场景配置、技能组合、OB 模板与用户操作流程。
- 图文、音频、视频任务的内容级编排与交付状态；自动执行和人工介入边界明确。
- 版本锁定、诊断、冲突检查、失败恢复和保留用户数据的升级/卸载。

## 外部责任

- Harness 是基于 DeepSeek Harness 搭建的插件系统基础；本仓精确运行版本、插件接口与兼容矩阵在实现时验证。
- dsh-oil-creator 是后续工作台形态参考；本仓尚未安装或完成适配，不预先确定全部体系。
- Obsidian 是知识库应用；只发行模板和受控配置，不复制用户现有 Vault。
- 工厂与后续工作台主要使用自有 WildFlow 模型服务。本仓通过接口引用，不复制账号、计费或 GPU 运维。
- 共用能力来源与版本必须明确；本次不假定已有完整共享包或新建它们的仓库。

## 数据与案例

现阶段不发布业务案例、项目模板或素材，也不复制任何实际业务项目仓。后续案例展示须另行明确批准。

发行模板、本机状态、用户资料和生成结果分离。两产品不共享默认凭据、运行目录或全局可变配置。
后台常驻、电脑休眠后的执行、内容质量、人工审核与发布授权均需分别验收。
原生桌面封装不会消除进程退出、休眠、断网或插件冲突；具体场景见[集成验收清单](integration-checklist.md)。
