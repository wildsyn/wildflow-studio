# 野生流动内容工作台产品方案

决策日期：2026-08-30。本文记录已确认的产品方向与实施边界；功能完成情况以 PR 和实际验收为准。
当前仍是治理与设计阶段，没有可运行客户端或经过验证的插件组合。

## 要做的产品

让创作者打开一个 Mac 应用，就能围绕自己的知识库完成选题、整理材料、讨论、创作、修改、审核
和交付。工作台同时展示内容项目、已有文件、当前进度与 AI 对话；用户不需要先配置终端、记端口
或在多个浏览器标签之间寻找当前内容。

先推进 wildflow-studio。wildflow-factory 保持独立仓库与产品边界，本阶段不并行建设其应用。
个人包暂不建仓，不建设统管这些产品的统一客户端。

## 已确认的选择

| 项目 | 决定 | 尚未完成的部分 |
|---|---|---|
| 产品对象 | 图文、音频、视频及组合内容 | 各媒体独立流程和交付验收 |
| 用户入口 | Mac 客户端优先，内部复用 Web 界面 | 安装包、签名、公证与真实用户安装 |
| 技术路线 | Electron 优先；DSH Desktop 为首选桌面复用候选 | 固定版本、原生能力与资源占用测试；Tauri 仅作为需要时的备选 |
| 内容工作台基础 | 基于 oil-oil/dsh-oil-creator 集成与扩展 | 与桌面宿主兼容、多媒体流程和知识库适配 |
| Agent 底座 | DeepSeek Harness 的插件与 Skills 机制 | 可发行的兼容版本组合 |
| 内容与知识库 | 普通文件、Markdown 与 Obsidian 配合 | 双向编辑、附件引用、冲突与恢复验证 |
| 发布责任 | 用户决定内容、审核成品及对外发布 | 可选渠道适配，不默认自动发布 |

## 如何基于 dsh-oil-creator

采用它的内容组织与交互基础：内容项目对应本地目录，正文与产物保持可读文件，工作台状态单独
保存，内容列表与检查器连接到 AI 对话，专业处理交给 Skills 或外部应用。这是本产品的功能基础，
不是只作为展示链接；但“确定基础”不代表已经完成代码引入。

上游主要围绕视频制作。我们把它扩展为“一项内容，一个项目”，项目可产生图文、音频、视频中的
一种或多种，不能把录制、视频导出、字幕和封面设置成所有内容的固定必经步骤。

| 沿用的基础 | 本产品的扩展 |
|---|---|
| 本地目录、Markdown、可观察的产物 | 与 Vault 内外的内容目录配合，支持媒体附件与知识来源链接 |
| 内容列表、检查器和对话上下文 | 支持不同内容类型各自的材料、阶段与待确认动作 |
| 创作者脚本规则 | 由用户配置受众、风格与禁忌，不内置上游作者的人设或真实业务资料 |
| 可选字幕、封面、录制/剪辑及文章能力 | 按能力组合并允许替换提供方，不要求所有创作者安装全部工具 |
| 内容状态与文件分离 | 产品独立的数据目录、版本迁移、失败诊断与恢复 |

在公开接口允许的范围内优先插件组合和本仓适配；扩展接口不足时才评估对该插件做可追溯的受控
修改，保留上游来源与许可。不默认 Fork DSH 核心，也不提前新建共享平台仓。

## 用户工作流

1. **首次配置**：用户选择内容目录或 Obsidian Vault；AI 辅助检查依赖并展示安装/配置方案。
2. **建立内容项目**：选择要产出的媒体类型，引用知识资料，记录选题与目标，不复制整份 Vault。
3. **共同创作**：列表、检查器与对话指向同一项目；AI 读写获准文件并调用用户选定的能力。
4. **审阅与修订**：预览各类成品，标明来源、执行状态、失败和仍需人工判断的环节。
5. **交付**：保留可继续编辑的文件及成品；导出或准备平台草稿与最终发布分开授权。

一键配置可以简化交互，但不能跳过来源核验、版本锁定、权限预览、失败恢复和用户数据保护。
现阶段不需要大型插件市场；先展示并管理经过验证的必要技能和插件。

## Mac 桌面与后续适配

- 应用自行启动本地服务、等待就绪并打开窗口；用户不填写 localhost 地址，也不依赖全局 `dsh` 命令。
- 每个产品有独立的应用标识、数据目录、运行实例、凭据作用域和更新渠道；复用代码不等于共享可变状态。
- 默认仅使用本机回环地址，由系统分配可用端口或使用经过验证的本地通信机制。不开放无鉴权局域网控制。
- 随机端口改变 origin；重要配置不能仅依赖浏览器 localStorage，现有 UI 插件要验证重启后的行为。
- 关闭窗口、退出应用和停止任务是不同操作。菜单栏展示后台状态，退出前提示未完成任务并持久化必要状态。
- 休眠、关机、断网和崩溃都要有明确结果；不能承诺仅凭本机客户端获得全天候执行能力。
- 平台相关路径、菜单、文件选择、进程、凭据存储及更新放到适配层。首阶段只验收 Mac，不能据此宣称 Windows 已兼容。

浏览器入口保留为开发、诊断和未来远程访问的补充，不另建一套业务前端。远程控制需要独立的安全
设计和授权，本阶段不开放。

## 更新与依赖

桌面壳、UI 与 DSH 核心先按验证过的应用版本组合交付；插件和 Skills 使用精确版本/commit 与
来源记录，更新前检查兼容性，不在启动时自动追最新。运行中的任务不能被无提示升级打断。
升级与卸载保护用户内容、项目状态和凭据，数据迁移需要备份、恢复路径与可验证结果。

Mac 正式分发包括签名、公证与更新包验证。上游 Desktop 当前的“检查更新后下载 DMG 并由用户
替换应用”不能直接写成我们已具备静默自动更新；实际行为见 [UPSTREAM](../UPSTREAM.md)。

## Obsidian 与可选能力

Obsidian 是外部知识库应用，不把它的本体嵌入或再分发。工作台连接用户选择的 Vault/目录，以普通
Markdown、附件和必要的应用跳转协作；任何 `.obsidian` 设置改动先预览和备份，不整体覆盖配置。
两端同时编辑、文件重命名、附件移动和符号链接边界都需要验证。

上游的 oil-subtitle、oil-cover、screen-studio-editor、oil-video-article 与 video-publisher 等
仅为可选能力候选，尚未逐项安装、审计或确定打包。Screen Studio、Ego Lite 及相关云服务的
安装、账号、费用、平台限制和许可各自独立；它们不能成为基础知识库与内容列表可用的前提。
本产品不绑定上游作者的模型渠道；执行能力按明确接口对接选定服务，避免重复实现账务和 GPU 调度。

## 验收与排除项

优先消除版本与布局兼容风险，再验证本地内容组织、各媒体流程、桌面生命周期与安装升级。
每一步都使用明确版本与临时合成数据，完整清单见[集成验收清单](integration-checklist.md)。

本次只记录方案，不安装插件、不复制上游源码、不修改用户 Vault、不调用付费服务、不创建
Tag/Release、不部署、不公开业务案例或素材。公开许可不等于任何业务内容的公开授权。
